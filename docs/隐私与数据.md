# 隐私与数据说明

这份文档回答三个问题：**程序在后台做了什么、存了什么、发出去了什么。**
同样的内容也写在程序里（设置 → 程序在后台做了什么），老师可以随时查看。

## 一、程序在后台做了什么

| 行为 | 频率 / 触发 | 能否关闭 |
|------|-------------|----------|
| 检查新版本 | 约每小时一次；启动时若距上次超过 10 分钟也会查 | 只能关"自动安装"（设置 → 自动更新）；检查本身不可关（只发一个版本查询请求） |
| 下载更新包 | 发现新版本后自动后台下载（约 200MB，多镜像源） | 同上 |
| 静默安装更新 | 连续 10 分钟无键鼠输入时（安装包会短暂关掉程序） | 设置 → 自动更新 → 关 |
| 重建快捷方式 | 每 30 秒检查桌面 / D 盘根目录，缺了就补 | 不可关（对抗冰点还原的设计） |
| 刷新早晚读时间段 | 每 10 分钟（仅在已登录时） | 不可关（悬浮球依赖它） |
| 清理下载残留 | 每小时 | 不可关 |
| 匿名统计上报 | 启动、更新检查/下载/安装、错误发生时 | 设置 → 隐私 → 关闭 |
| 关闭窗口后驻留托盘 | 点 ✕ 之后 | 右键托盘 → 退出（结束后台） |

## 二、本地存了什么

全部在 `D:\IdiotLaunch\data`（选择 D 盘是因为教室电脑 C 盘通常有冰点还原）：

| 文件 | 内容 | 敏感性 |
|------|------|--------|
| `morning_config.json` | 早读年级、班级号、**班级密码**（XOR+Base64 混淆）、时间段 | ⚠️ 同机其他账号可还原出密码 |
| `morning_api_cache.json` | 早读 token、InfinityFree 挑战 cookie | ⚠️ 有效期内可用于调用班级接口；退出登录时会删除 |
| `state.json` | 更新状态、待安装的更新包路径 | 低 |
| `settings.json` | 主题、自动更新开关、统计开关 | 低 |
| `*.log` | 运行日志（不含密码；错误信息可能含路径） | 低 |
| `IdiotLaunch_Setup_*.exe` | 下载好的更新包 | 低（安装后自动清理） |

**注意**：`D:\IdiotLaunch\data` 对同一台电脑的所有用户可读写。若一台电脑多人共用同一
Windows 账号（教室电脑常见），请**不要勾选"记住登录"**，并教导老师下课点「退出登录」。
彻底卸载会删除整个 `D:\IdiotLaunch`（含以上全部数据）。

## 三、发出去什么

### 1）版本查询与更新下载

- 请求 `tiofmybnepcheudfgysa.supabase.co`（查询最新版本号/下载地址/SHA-256）。
- 请求 `api.github.com`、`github.com` 及若干 `ghproxy` 类镜像站（下载安装包）。
- 这些请求**只包含程序版本号**这类通用信息，不包含班级、账号、密码。

### 2）匿名统计（可关闭）

上报到同一个 Supabase 项目，每条记录包含：

| 字段 | 内容 |
|------|------|
| `version` | 程序版本号 |
| `event_type` | 事件类型（启动 / 更新检查 / 下载成功失败 / 安装 / 错误） |
| `os_version` | Windows 版本字符串 |
| `details` | 事件细节：**匿名机器标识**（注册表 MachineGuid 的 SHA-256 前 16 位，不可逆）、本次会话随机 ID、进程号、时间戳、错误类型与错误位置、下载耗时/大小等 |

**不包含**：班级、年级、姓名、密码、token、文件内容、键盘记录、屏幕截图、路径中的用户名。

用途：判断"某个问题是所有学校都遇到，还是某台电脑特有的"，以及定位更新失败原因。

限制：每天最多上报 300 条（错误类 120 条），同类事件 30 分钟内去重——既是隐私最小化，
也是为了不超出 Supabase 免费额度。

关闭方式：**设置 → 隐私 → 匿名运行统计**（关闭后不再上报，已有记录不会追溯删除；
如需要删除历史数据请联系作者）。
